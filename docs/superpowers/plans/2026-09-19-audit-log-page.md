# The Audit Log Page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A team's admins and owners can open `/teams/$teamSlug/audit-log`, read who did what and when in their own language, narrow it by entity type, actor and time range, and share the URL of what they are looking at.

**Architecture:** Two pure modules carry the logic worth testing on its own — the search-parameter/date-boundary conversion and the actor resolution. Two server functions fetch the log and the member list through the existing `...For`/`...Fn`/`...QueryOptions` triple. The page composes a table whose rows disclose their own metadata, and the sidebar entry is gated by the role already present in the membership list.

**Tech Stack:** TanStack Start/Router/Query, react-i18next, shadcn/ui on Base UI (`table`, `pagination`, `native-select`, `input`, `button`, `empty`), Vitest + Testing Library + axe-core, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-19-audit-log-page-design.md`

## Global Constraints

- **No API change.** `GET /v1/teams/{team_id}/audit-log` and `GET /v1/teams/{team_id}/members` already exist and `packages/api-client` is already generated for both. Nothing in `apps/api`, `openapi.json` or `packages/api-client` is touched by this plan.
- **`from` is the start of its day and `to` is the end of its day, both in UTC.** The endpoint filters `created_at <= to` against a `timestamptz`. A day sent as midnight drops almost all of the day the reader picked, and "to: today" then hides today's entries.
- **Entries render newest first**, which is the query's own `created_at desc, id desc`. Do not re-sort client-side.
- **The German word for the `tag` entity is "Schlagwort", never "Tag".** The German catalogue already uses "Tag"/"Tage" exclusively for _day_ — five times on the statistics page — and this page is full of timestamps.
- **The sidebar entry renders only for `admin` and `owner`**, and the route still renders the refusal: a hidden menu entry is not a permission. A member below admin gets **403**; a non-member gets **404**.
- **Metadata keys render raw.** They are protocol vocabulary, like the dimension values `stat-breakdown-card.tsx` prints; they join `e2e/i18n.spec.ts`'s `IDENTICAL_BY_DESIGN`.
- `apps/web/src/components/ui/` is `shadcn add` output and is never hand-edited. This plan adds no new primitive — the disclosure is built from a button and a second row.
- **JSDoc tags are required on any function carrying a doc comment**; a destructured props object needs the parent tag plus a dotted tag per property.
- **`pnpm run lint` must print nothing but `$ oxlint`.** Warnings are a regression, not a baseline.
- **Commits** follow Conventional Commits, max 50 characters including type and scope. No co-author line and no generator footer, ever.
- **All git writes go through GitButler (`but`)** — never `git add`, `git commit`, `git checkout`. The lane is `feat/audit-log-page`, which already carries the spec commit.
- Run `pnpm format` before each commit. Never bypass Lefthook.
- `apps/web/src/routeTree.gen.ts` **is** regenerated by this plan — Task 7 adds a route — and is committed with it.

```ts
/** The entity types `GET /v1/teams/{team_id}/audit-log` accepts, as its own enum declares them. */
export const AUDIT_ENTITY_TYPES = [
	'domain',
	'folder',
	'link',
	'tag',
	'team',
	'team_member',
] as const;

export type AuditEntityType = (typeof AUDIT_ENTITY_TYPES)[number];

/** The page's filters, exactly as they live in the route's search parameters. */
export interface AuditFilters {
	/** A user id, passed through opaquely; the API validates it and answers 422 itself. */
	readonly actor?: string;
	readonly entityType?: AuditEntityType;
	/** The first day to include, as YYYY-MM-DD. */
	readonly from?: string;
	/** 1-based, like every other paginated list in this app. */
	readonly page: number;
	/** The last day to include, as YYYY-MM-DD. */
	readonly to?: string;
}

/** A calendar day exactly as the controls produce it and the URL carries it. */
const DAY = /^\d{4}-\d{2}-\d{2}$/u;

/**
 * Anything at all can arrive in a search parameter — a bookmark from an older
 * build, a hand-edited URL, a stale link in an email. Every value is therefore
 * checked rather than cast, and a value that fails is dropped rather than
 * corrected: a filter the reader did not ask for is worse than no filter,
 * because the page would then quietly show a subset while looking complete.
 *
 * @param search - The route's raw search object.
 * @returns The filters, with every unusable value removed.
 */
export function parseAuditFilters(
	search: Readonly<{
		actor?: unknown;
		entityType?: unknown;
		from?: unknown;
		page?: unknown;
		to?: unknown;
	}>,
): AuditFilters {
	const page =
		typeof search.page === 'number' && Number.isInteger(search.page) && search.page >= 1
			? search.page
			: 1;

	return {
		...(typeof search.actor === 'string' && search.actor !== '' && { actor: search.actor }),
		...(typeof search.entityType === 'string' &&
			(AUDIT_ENTITY_TYPES as readonly string[]).includes(search.entityType) && {
				entityType: search.entityType as AuditEntityType,
			}),
		...(typeof search.from === 'string' && DAY.test(search.from) && { from: search.from }),
		page,
		...(typeof search.to === 'string' && DAY.test(search.to) && { to: search.to }),
	};
}

/**
 * Turns the two chosen days into the instants the endpoint filters on.
 *
 * `to` becomes the **last** millisecond of its day, not its first. The endpoint
 * compares `created_at <= to` against a `timestamptz`, so a day sent as
 * midnight would exclude everything that happened during it — choose "to:
 * today" and today's entries vanish, which reads as a broken log rather than
 * an off-by-one.
 *
 * Both are read as UTC, the convention the statistics window already uses
 * because the click rollup buckets in UTC. A reader west of Greenwich choosing
 * "today" therefore gets the UTC day, which is the same answer every other
 * date in this product gives.
 *
 * @param filters - The parsed filters.
 * @returns The `from`/`to` query values, each omitted when its day was not chosen.
 */
export function toQueryRange(filters: Readonly<Pick<AuditFilters, 'from' | 'to'>>): {
	from?: string;
	to?: string;
} {
	return {
		...(filters.from !== undefined && { from: `${filters.from}T00:00:00.000Z` }),
		...(filters.to !== undefined && { to: `${filters.to}T23:59:59.999Z` }),
	};
}
```

```ts
/** What the page can say about who wrote an entry. */
export type ActorDisplay =
	| { readonly email: string; readonly kind: 'member' }
	| { readonly kind: 'deletedAccount' }
	| { readonly kind: 'formerMember' };

/**
 * Decides which of the three things the page can truthfully say about an
 * entry's actor.
 *
 * The distinction between the last two is the point. "A former member" is a
 * fact about this team — the membership was deleted and the entries were
 * deliberately not. "A deleted account" is a fact about the person, and
 * reaches us as a null id because `audit_log.actor_user_id` is
 * `on delete set null`. Showing one for the other would tell a board that
 * somebody left when they did not.
 *
 * @param actorUserId - The entry's `actor_user_id`, absent when the account is gone.
 * @param membersById - The team's current members, keyed by user id.
 * @returns What to render for this actor.
 */
export function resolveActor(
	actorUserId: string | undefined,
	membersById: ReadonlyMap<string, string>,
): ActorDisplay {
	if (actorUserId === undefined) return { kind: 'deletedAccount' };

	const email = membersById.get(actorUserId);
	return email === undefined ? { kind: 'formerMember' } : { email, kind: 'member' };
}
```

```ts
import { listAuditLog, type PageAuditEntry } from '@kurze-url/api-client';
import { createServerFn, createServerOnlyFn } from '@tanstack/react-start';
import { getRequest } from '@tanstack/react-start/server';
import { queryOptions } from '@tanstack/react-query';

import type { AuditFilters } from '../lib/audit-filters';
import { toQueryRange } from '../lib/audit-filters';
import { authedApiClient } from './api';
import { flushSessionCookies, requireSession } from './session';

/** The page size every paginated list in this app uses. */
const PER_PAGE = 20;

export const listAuditLogFor = createServerOnlyFn(
	async (request: Request, teamId: string, filters: AuditFilters): Promise<PageAuditEntry> => {
		const headers = new Headers();
		const { accessToken } = await requireSession(request, headers);
		flushSessionCookies(headers);

		const { data } = await listAuditLog({
			client: authedApiClient(accessToken),
			path: { team_id: teamId },
			// `throwOnError` for the same reason `listLinksFor` gives: the
			// generated client's default never rejects, so a refused request
			// would resolve to `{ data: undefined, error }` and this page would
			// render an empty log instead of the refusal it must show.
			query: {
				...(filters.actor !== undefined && { actor_user_id: filters.actor }),
				...(filters.entityType !== undefined && { entity_type: filters.entityType }),
				...toQueryRange(filters),
				page: filters.page,
				per_page: PER_PAGE,
			},
			throwOnError: true,
		});
		return data;
	},
);

export const listAuditLogFn = createServerFn({ method: 'GET' })
	.validator((data: { readonly filters: AuditFilters; readonly teamId: string }) => data)
	.handler(
		async ({
			data,
		}: {
			readonly data: { readonly filters: AuditFilters; readonly teamId: string };
		}) => listAuditLogFor(getRequest(), data.teamId, data.filters),
	);

/**
 * One definition of the key and the fetcher, the same reason
 * `linksQueryOptions` gives: two definitions drift, and the symptom is a list
 * that updates on navigation but not after a filter changes. Every filter is
 * part of the key, so changing one is a different query rather than a stale
 * hit on the old one.
 *
 * @param teamId - The team whose log to read.
 * @param filters - The active filters, including the page.
 * @returns Query options keyed on the team and every filter.
 */
// oxlint-disable-next-line typescript/explicit-function-return-type, typescript/explicit-module-boundary-types -- same missing annotation as `linksQueryOptions`; see its own note.
export const auditLogQueryOptions = (teamId: string, filters: AuditFilters) =>
	queryOptions({
		queryFn: async () => listAuditLogFn({ data: { filters, teamId } }),
		queryKey: ['audit-log', teamId, filters] as const,
	});
```

- [ ] **Step 4: Write `server/members.ts`**

The same triple, for `listTeamMembers`. The member list is fetched only to turn actor ids into addresses, so it takes no filters and one page of 100 — a Verein's team is small, and a second page would mean an actor silently falling back to "a former member".

```ts
import { listTeamMembers, type PageMember } from '@kurze-url/api-client';
import { createServerFn, createServerOnlyFn } from '@tanstack/react-start';
import { getRequest } from '@tanstack/react-start/server';
import { queryOptions } from '@tanstack/react-query';

import { authedApiClient } from './api';
import { flushSessionCookies, requireSession } from './session';

/**
 * The API caps `per_page` at 100. Asking for the cap is deliberate: this list
 * exists to resolve actor ids, and an actor on page two would be rendered as a
 * former member — wrong, and wrong quietly. A team large enough to need paging
 * here needs a different approach, not a second request bolted on.
 */
const PER_PAGE = 100;

export const listMembersFor = createServerOnlyFn(
	async (request: Request, teamId: string): Promise<PageMember> => {
		const headers = new Headers();
		const { accessToken } = await requireSession(request, headers);
		flushSessionCookies(headers);

		const { data } = await listTeamMembers({
			client: authedApiClient(accessToken),
			path: { team_id: teamId },
			query: { page: 1, per_page: PER_PAGE },
			throwOnError: true,
		});
		return data;
	},
);

export const listMembersFn = createServerFn({ method: 'GET' })
	.validator((data: { readonly teamId: string }) => data)
	.handler(async ({ data }: { readonly data: { readonly teamId: string } }) =>
		listMembersFor(getRequest(), data.teamId),
	);

/**
 * @param teamId - The team whose members to list.
 * @returns Query options keyed on `['members', teamId]`.
 */
// oxlint-disable-next-line typescript/explicit-function-return-type, typescript/explicit-module-boundary-types -- same missing annotation as `linksQueryOptions`; see its own note.
export const membersQueryOptions = (teamId: string) =>
	queryOptions({
		queryFn: async () => listMembersFn({ data: { teamId } }),
		queryKey: ['members', teamId] as const,
	});
```
