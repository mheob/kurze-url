# CLI Part 2 — Consent Page and Web Sign-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The web app hosts the page Supabase's OAuth server sends a CLI login to. The page is `/oauth/consent`, with allow and deny, reachable through the magic-link login. Web sign-out becomes local by default, with a "Sign out everywhere" checkbox.

**Architecture:**

- **Consent page:** a standalone route, `src/routes/oauth.consent.tsx`, laid out like `login.tsx` and outside `_authed`, so it needs a session but no team. Its loader calls one server function. That function reads the session from the SSR cookies and asks `supabase.auth.oauth.getAuthorizationDetails`. It answers with one of four states:
  - the person is not signed in;
  - the authorization is invalid;
  - the consent was already given, so the page redirects;
  - the consent is still open. Allow and Deny call a second server function, then follow the returned URL with `window.location.assign`.
- **Login round trip:** a `next` parameter carries the consent URL through `/login` and the magic link to `/auth/callback`. Only a same-origin path that starts with `/oauth/consent?` is ever honoured.
- **Sign-out:** `signOut` takes a scope.

**Tech Stack:** TanStack Start (React) with `createServerFn`, `@supabase/ssr` and `@supabase/auth-js` 2.118 (`auth.oauth.*`). The UI uses shadcn on Base UI (`ui/card`, `ui/button`, `ui/checkbox`) and react-i18next. Tests use Vitest with RTL, Storybook with the a11y addon, and Playwright with `@axe-core/playwright`.

**Spec:** `docs/superpowers/specs/2026-10-23-cli-design.md`, Part 2, plus the "Verified (2026-10-23)" and "Maintainer setup" sections from Part 1 (#145).

- **Generated files:** never hand-edit `src/components/ui/*`. `src/routeTree.gen.ts` is regenerated by `pnpm --filter @kurze-url/web build`, and is committed only because a new route makes it necessary.
- **Consent copy is fixed** (spec, Part 2). The keys live under `oauthConsent`, each listed here as key: English / German:
  - `title`: "Allow CLI access" / "CLI-Zugriff erlauben"
  - `request`: "{{client}} wants to access kurze-url on your behalf." / "{{client}} möchte in deinem Namen auf kurze-url zugreifen."
  - `scope`: "It can then do everything you can do in the web app, in every team you belong to." / "Sie kann dann alles, was du in der Web-App darfst, in allen deinen Teams."
  - `warning`: "Only allow this if you just ran kurze-url login in your terminal yourself." / "Erlaube das nur, wenn du gerade selbst kurze-url login im Terminal ausgeführt hast."
  - `signedInAs`: "Signed in as {{email}}" / "Angemeldet als {{email}}"
  - `allow`: "Allow" / "Erlauben"
  - `deny`: "Deny" / "Ablehnen"
  - `invalidTitle`: "This request can't be completed" / "Diese Anfrage lässt sich nicht abschließen"
  - `invalidBody`: "The link has expired or is not valid. Run kurze-url login in your terminal again." / "Der Link ist abgelaufen oder ungültig. Führe kurze-url login im Terminal erneut aus."
- **Sign-out copy:** `auth.signOutEverywhere`: "Sign out everywhere" / "Überall abmelden".
- **Open-redirect rule** (spec): honour `next` only when it is a same-origin path starting with `/oauth/consent?`. Everything else falls back to `/`.
- **Already consented** (Verified): `getAuthorizationDetails` then returns `redirect_url` and **no** `authorization_id`.
- **Server calls:** `approveAuthorization` and `denyAuthorization` run on the server with `{ skipBrowserRedirect: true }`, and return `redirect_url`.
- **Sentry:** user-visible states (not signed in, invalid, already consented) are rendered, never reported.

## Review Focus

1. **A crafted `next`:** `//evil.example`, `/\evil.example`, `https://evil.example/oauth/consent?x`, `/oauth/consentx?authorization_id=1`, a `next` carrying a newline or `%0d%0a`, and an empty string must all be refused, falling back to `/`. Task 1's table test lists each.
2. **A missing, empty or unknown `authorization_id`:** the error card renders, with no throw and no Sentry event. Tests are in Task 3 (server) and Task 4 (route).
3. **A double click on Allow:** only one decision is sent, because both buttons are disabled while it is pending. Task 4 tests it.
4. **A session that expires between loading the page and clicking:** the decision answers "unauthenticated", and the page goes to `/login` with the same `next`. Tests are in Task 3 and Task 4.
5. **The sign-out checkbox:** unchecked by default; Space toggles it; the label is clickable; unchecked sends `local` and checked sends `global`. Task 5 tests it.

export type ConsentState =
	| { readonly kind: 'consent'; readonly authorizationId: string; readonly clientName: string; readonly email: string }
	| { readonly kind: 'invalid' }
	| { readonly kind: 'redirect'; readonly url: string }
	| { readonly kind: 'unauthenticated' };

export const decideConsentFor: (request: Request, headers: Headers, decision: Readonly<{ action: 'approve' | 'deny'; authorizationId: string }>) => Promise<ConsentDecision>; // createServerOnlyFn
