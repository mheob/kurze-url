# Tags Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tags reach `apps/web`. The work has four parts:

- a tags page;
- a tag picker on the link form, as a combobox with chips that can also create tags;
- a tag column on the link list;
- a single-tag filter on that list.

It also extracts the folder management components into shared ones.

**Architecture:**

- **API.** One API correction gives the unknown-tag 422 a location.
- **Shared extraction.** The folders slice's management UI is extracted into components shared by folders and tags: `NameForm`, `NameList`, `NameManagementBody` and the `useNameMutations` hook. The folders page then uses them, with unchanged behavior.
- **Tags.** Tags get server functions (a two-page list, since the cap is 200), a tags page, a picker built on the generated shadcn combobox (Base UI 1.8), and link-list support through a combined `LinkFilter`.

**Tech Stack:** Go (Huma), TanStack Start/Router/Query/Form, shadcn on Base UI 1.8 (combobox), react-i18next, Vitest + RTL + MSW, Storybook, Playwright + axe.

**Spec:** `docs/superpowers/specs/2026-10-02-tags-frontend-design.md`. Read it before any task.

## Rulings on the spec

Reading the code and the shadcn registry while writing this plan settled two things the spec left open.

1. **The registry ships the combobox with chips** for `base-sera`, so the spec's fallback (composing Base UI by hand) is not needed.
   - `shadcn view combobox` exports `Combobox`, `ComboboxChips`, `ComboboxChip`, `ComboboxChipsInput`, `ComboboxContent`, `ComboboxList`, `ComboboxItem`, `ComboboxEmpty` and `useComboboxAnchor`.
   - It also pulls in `input-group` as a registry dependency.
2. **The generated `ComboboxChip` renders its remove button with no accessible name**: an icon-only `ChipRemove`, and no prop that can label it. Its file may not be hand-edited (`CLAUDE.md`, `components/ui/`).
   - `tag-picker.tsx` therefore renders every chip with `showRemove={false}` and adds its own `Combobox.ChipRemove` from `@base-ui/react`, labelled `t('links.tagRemove', { name })`.
   - This follows the precedent of wrapping `SidebarTrigger` (`CLAUDE.md`, "Two golden rules collide…").
   - The Storybook a11y check would fail on the bare generated chip.

## Global Constraints

- **Naming.** The tenant is `team` in every identifier. "Verein" appears only in German copy, where the subject is the tenant.
- **No hardcoded user-facing strings.** Every key exists in `en.json` and `de.json`.
  - `catalogues.test.ts` rejects keys with identical English and German values unless they are listed in its identical-by-design list. "Tags" and "Tag" are identical in both languages, so add each such key there.
  - `e2e/i18n.spec.ts` has its own identical-word list. Add "Tags" and "Tag" to it as well.
- **Accessibility.** WCAG 2.1 AA. Visible labels; every icon button has an accessible name; Storybook a11y (`a11y: { test: 'error' }`) and axe in e2e must pass.
- **JSDoc.** A function with a `/** … */` block needs `@param`, including dotted tags for destructured props, and `@returns`.
- **Tooling.** oxlint and oxfmt only. `pnpm lint` must report zero warnings; `pnpm typecheck` must pass. For `max-params`, bundle parameters into an object the way `server/members.ts` does, never with a disable comment. Suppress other rules only where an existing file sets the precedent.

- **Tolerant loading.** Link pages load tags tolerantly (`prefetchTags` never rejects) and read them with a non-suspense `useQuery`. The tags page loads them strictly.
- **Tenancy.** Every query keeps its `team_id` predicate.
- **Commits.**
  - Through GitButler only, on the lane `feat/tags-frontend`, via the `create-commit` skill.
  - Subject at most 50 characters; no co-author or generator footer.

import type { FolderGoneQueryClient } from './folders';

/** Mirrors maxTagsPerTeam in apps/api/internal/api/limits.go. */
export const TAGS_PER_TEAM = 200;
/** Mirrors maxTagsPerLink in apps/api/internal/api/limits.go. */
export const TAGS_PER_LINK = 10;

/**
 * Whether two tag-id lists name the same set, ignoring order — what decides
 * whether an edit sends `tag_ids` at all.
 *
 * @param a - One list of tag ids.
 * @param b - The other.
 * @returns True when both name exactly the same tags.
 */
export function sameTagSet(a: readonly string[], b: readonly string[]): boolean {
	if (a.length !== b.length) return false;
	const set = new Set(a);
	return b.every((id) => set.has(id));
}

/** What `remapTagGoneFailure` needs from its caller. */
export interface TagGoneRemapDeps {
	readonly queryClient: FolderGoneQueryClient;
	readonly tagGoneMessage: string;
	readonly teamId: string;
}

/**
 * The tag counterpart of `remapFolderGoneFailure`: a 422 on `body.tag_ids`
 * means a chosen tag was deleted meanwhile, so the field gets our own message
 * and the tags are refetched, which lets the picker mark the stale chip.
 *
 * @param classified - The failure `classifyApiError` produced.
 * @param deps - The message, query client and team.
 * @returns The failure, with the tag field's message replaced when it applies.
 */
export function remapTagGoneFailure(classified: ApiFailure, deps: TagGoneRemapDeps): ApiFailure {
	if (classified.kind !== 'fields' || classified.fields.tag_ids === undefined) return classified;
	void deps.queryClient.invalidateQueries({ queryKey: ['tags', deps.teamId] });
	return { ...classified, fields: { ...classified.fields, tag_ids: deps.tagGoneMessage } };
}

```ts
/**
 * Creates a tag from the link form's picker. A 409 means the name exists
 * already (in some case — names are unique case-insensitively), so the tags
 * are refetched and that tag is returned instead of an error.
 *
 * @param teamId - The team the tag belongs to.
 * @returns A function that creates a tag by name.
 */
export function useCreateTag(teamId: string): (name: string) => Promise<TagCreateResult> {
	const { t } = useTranslation();
	const queryClient = useQueryClient();
	return async (name) => {
		try {
			const tag = await createTagFn({ data: { name, teamId } });
			void queryClient.invalidateQueries({ queryKey: ['tags', teamId] });
			return { tag: { id: tag.id, name: tag.name } };
		} catch (error) {
			if (statusOf(error) === HTTP_CONFLICT) {
				const tags = await queryClient.fetchQuery({ ...tagsQueryOptions(teamId), staleTime: 0 });
				const existing = tags.find((tag) => tag.name.toLowerCase() === name.toLowerCase());
				if (existing) return { tag: { id: existing.id, name: existing.name } };
			}
			const tags = queryClient.getQueryData(tagsQueryOptions(teamId).queryKey) ?? [];
			const failure = nameFailureOf(error, tags.length >= TAGS_PER_TEAM);
			const key =
				failure === 'rateLimited' || failure === 'unknown' || failure === 'unauthenticated'
					? `errors.${failure === 'unauthenticated' ? 'unknown' : failure}`
					: `tags.${failure}`;
			return { error: t(key) };
		}
	};
}
```
